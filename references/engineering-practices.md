# 工程实践与可持续迭代详情

> SKILL.md §7 的完整展开：工程实践五层内涵的完整阐述。规划项目结构、构建/发布流程、迭代节奏与知识沉淀时阅读。

> 磨刀不误砍柴工。良好的工程实践是项目能够长期、可持续迭代的基础，而不是可选项。

它包含五层内涵：

1. **工程整洁有序**：目录结构合理、文档与代码同步更新、及时清除冗余代码与过期概念；团队共用一套清晰、规范的术语与命名，避免同一事物在不同模块、文档、接口中出现多个名字。
2. **先调研，再设计，最后编码**：在动手实现前，先充分理解问题域和现有约束；优先确定落盘数据格式、协议契约和 API 边界，再进入编码。不要随意跳过调研与设计环节，用“先跑起来”替代“先想清楚”。
3. **MVP 之后继续打磨原型**：最小可运行闭环验证通过后，不要立刻进入下一个开发周期。应基于设计目标反复迭代原型，替换占位实现、补齐边界情况、验证真实场景，直到当前阶段的目标真正达成，再开启下一周期。
4. **随时可构建、可验证、可发布**：项目中任何物料——无论是代码、美术资源还是策划配置——都能在任何时刻经过各自的转化流程产出可运行的最终产物，并配有可用的验证环境；构建、验证、发布的操作优先用自动化脚本和系统固化，只在自动化无法覆盖的环节以文档补充，确保团队中任何人都不依赖口头知识即可独立完成。
5. **持续回顾，沉淀决策**：在关键迭代节点主动回顾自己的工作，将设计决策、取舍原因和经验教训写入决策历史与设计文档，让知识从个人记忆变为项目资产，降低后续迭代的信息损耗。
