# 迁移与大规模重构详情

> SKILL.md §4 的完整展开：变更边界的完整说明、旧层隐式行为清单与症状延迟暴露分析。进行框架迁移、大版本升级、大规模重构时阅读。

## 4.1 变更边界原则

在升级、迁移或大规模重构期间，错误数量可能激增。修复错误时必须先判断该错误是否与本次修改直接相关：

- 仅修复由本次改动引入的问题；
- 若错误与本次修改无关，必须高度警惕，停止修复并主动与相关方协商，不能为了消错而改动无关代码。

## 4.2 迁移前梳理旧层隐式行为

任何框架迁移（如 Dojo→React、Redux→Hooks、UI 库大版本升级）之前，**必须先系统梳理旧层自动做了什么**——URL 映射、公共参数注入、Content-Type 协商、错误处理流程、状态管理副作用等。逐项列清单，确认新层是否覆盖。

不能仅凭"UI 渲染出来了"就认为迁移成功。隐式行为丢失的症状往往延迟暴露：页面能加载但 API 返回参数无效，表单能提交但后端收不到字段，功能在简单路径下正常但在边界条件下静默失败。
